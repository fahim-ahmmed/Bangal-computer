# Bangal Computer

StarTech.com.bd-এর স্ট্রাকচার, ক্যাটাগরি ও ফিচার অনুসরণ করে বানানো নিজস্ব ব্র্যান্ডের ই-কমার্স সাইট।

## Stack
- **Frontend:** Next.js (App Router) + Tailwind CSS + HeroUI
- **Backend:** Node.js + Express.js (REST API) — সম্পূর্ণ আলাদা সার্ভার
- **Database:** MongoDB (Mongoose ODM)
- **Auth:** Better Auth (Email/Password, OTP, Google/Facebook OAuth, Role-based: customer/staff/admin)
- **Admin UI:** Gravity UI (ড্যাশবোর্ড, টেবিল, ফর্ম-হেভি স্ক্রিনের জন্য)

## Monorepo Structure
```
bangal-computer/
├── apps/
│   ├── web/      → Next.js frontend (customer site + /admin route group)
│   └── api/      → Express.js backend (REST API, আলাদা প্রসেসে চলে, আলাদা পোর্টে)
├── packages/
│   └── shared-types/  → দুই সাইডে শেয়ার করা constants/JSDoc types
└── package.json  → npm workspaces root
```

**Frontend ও Backend সম্পূর্ণ আলাদা** — `apps/web` (Next.js, পোর্ট 3000) এবং `apps/api` (Express, পোর্ট 5000) আলাদা প্রসেস হিসেবে চলবে, `apps/web` শুধু `NEXT_PUBLIC_API_URL` দিয়ে `apps/api`-কে কল করবে। এতে ভবিষ্যতে backend আলাদা সার্ভারে ডিপ্লয় করা, স্কেল করা এবং mobile app/other client যোগ করা সহজ হবে। Auth (Better Auth) চলবে Next.js সাইডে (session cookie হ্যান্ডেল করার জন্য সবচেয়ে সহজ পথ), আর Express API প্রতিটা রিকোয়েস্টে সেই সেশন ভেরিফাই করবে।

## Part 1 — এই পার্টে যা আছে
1. Monorepo + workspace সেটআপ
2. MongoDB কানেকশন (Express সাইড)
3. Better Auth সেটআপ (Email/Password + OTP + Google/Facebook OAuth + role: customer/staff/admin)
4. Tailwind + HeroUI (web) ইন্টিগ্রেশন, Gravity UI ডিপেন্ডেন্সি রেডি (admin অংশ Part 7-এ পূর্ণাঙ্গ হবে)
5. বেসিক লেআউট — Header/Footer স্কেলিটন, হোমপেজ প্লেসহোল্ডার
6. ক্যাটাগরি Schema + এক্সেল থেকে ১৮টি Main Category + ১৪৫৯টি Subcategory/Brand সিড করার script

## চালানোর নিয়ম (পরে, নিজের মেশিনে)
```bash
npm install                      # রুট থেকে, সব workspace ইনস্টল হবে
cp apps/api/.env.example apps/api/.env      # MONGODB_URI, PORT ইত্যাদি বসান
cp apps/web/.env.example apps/web/.env.local # BETTER_AUTH_SECRET, DB URL, API URL বসান

npm run seed:categories          # ক্যাটাগরি ট্রি MongoDB-তে সিড হবে
npm run dev:api                  # Express সার্ভার (http://localhost:5000)
npm run dev:web                  # Next.js সার্ভার (http://localhost:3000)
```

> নোট: এই কন্টেইনারে ইন্টারনেট অ্যাক্সেস নেই, তাই এখানে `npm install` চালিয়ে টেস্ট করা যায়নি। কোড সঠিকভাবে লেখা হয়েছে, আপনার মেশিনে `npm install` করার পর চলবে। কোনো এরর পেলে আমাকে জানাবেন, ঠিক করে দেব।

## Part 2 — এই পার্টে যা যোগ হলো
1. Category API সম্পূর্ণ CRUD (admin/staff role-protected) — main/sub add-edit-softdelete, reorder endpoint
2. Subcategory-তে ব্র্যান্ড add/remove API (মেগামেনুর ৩য় লেভেল)
3. Brand কালেকশনের নিজস্ব CRUD (canonical brand list, admin panel-এর "ব্র্যান্ড ম্যানেজমেন্ট" ফিচার)
4. `/categories/resolve/:main/:sub?/:brand?` — এক এন্ডপয়েন্টে ১-৩ সেগমেন্ট রেজলভ করে (storefront রুটের জন্য)
5. পূর্ণ ৩-লেভেল মেগামেনু কম্পোনেন্ট — startech.com.bd-এর মতো hover প্যানেল, সাবক্যাটাগরি + পাশে ব্র্যান্ড চিপ, "সব দেখুন" লিংক
6. ডাইনামিক রুট: `/[category]`, `/[category]/[subcategory]`, `/[category]/[subcategory]/[brand]` — প্রতিটায় ব্রেডক্রাম্ব
7. হোমপেজ এখন সিড করা আসল ১৮টি ক্যাটাগরি থেকে গ্রিড রেন্ডার করে
8. Admin ক্যাটাগরি/ব্র্যান্ড ম্যানেজমেন্ট পেজ (Gravity UI: Table, Select, TextInput, Card) — `/admin/categories`

> নোট: প্রোডাক্ট এখনো তৈরি হয়নি (Part 3-এ), তাই ক্যাটাগরি/সাব/ব্র্যান্ড পেজে এখন শুধু নেভিগেশন দেখাচ্ছে, প্রোডাক্ট গ্রিড না। মেগামেনু ও ক্যাটাগরি স্ট্রাকচার startech.com.bd-এর ১৮টি Main Category + সব Subcategory + সব Brand-এর সাথে হুবহু মিলিয়ে সিড করা।

## Part 3 — এই পার্টে যা যোগ হলো
1. Product schema (title, slug, category/subcategory/brand ref, price, discountPrice, stock, sku, images[], dynamic specs (key-value), description, variants[], rating, isFeatured, Draft/Publish status, isActive)
2. Product CRUD API — public (list/detail, published+active only) ও admin (all statuses, role-protected)
3. Draft/Publish টগল এন্ডপয়েন্ট (`PATCH /:id/status`)
4. Cloudinary ইমেজ আপলোড — multiple image (`POST /:id/images`), reorder (`PUT /:id/images/reorder`), single delete (`DELETE /:id/images`)
5. বাল্ক ইমপোর্ট (CSV/Excel) — `POST /products/bulk-import`, category/subcategory/brand নাম দিয়ে ম্যাচ করে, প্রতিটা স্কিপড/এরর রো রিপোর্ট করে। নমুনা টেমপ্লেট: `apps/api/src/data/product_bulk_import_template.csv`
6. Soft delete (`isActive: false`), text সার্চ ইনডেক্স (title+description)

> নোট: `.env`-এ Cloudinary credentials (`CLOUDINARY_CLOUD_NAME/API_KEY/API_SECRET`) বসাতে হবে ইমেজ আপলোড কাজ করার জন্য। এই পার্টে Admin-সাইড প্রোডাক্ট ফর্ম (frontend) নেই — সেটা এখনো backend-only; ফ্রন্টএন্ড লিস্টিং/ডিটেইলস Part 4-তে।

## Part 4 — এই পার্টে যা যোগ হলো
1. Product listing API-তে filter/sort/facet যোগ হলো — minPrice/maxPrice, brand (multi), sort (newest/price_asc/price_desc/featured), এবং প্রতিটা রেসপন্সে price range + brand counts (facets) — ঠিক StarTech-এর সাইডবার ফিল্টারের মতো
2. `GET /products/:slug/related` — একই সাবক্যাটাগরির সম্পর্কিত প্রোডাক্ট
3. **ফ্রন্টএন্ড লিস্টিং পেজ** (`/[category]`, `/[category]/[subcategory]`, `/[category]/[subcategory]/[brand]`) — সব একটা শেয়ার্ড `CategoryListingLayout`-এ: প্রাইস রেঞ্জ + ব্র্যান্ড চেকবক্স ফিল্টার (সাইডবার), সর্ট ড্রপডাউন, প্রোডাক্ট গ্রিড, পেজিনেশন — সব URL query param-চালিত (শেয়ারযোগ্য লিংক)
4. **প্রোডাক্ট ডিটেইলস পেজ** (`/product/[slug]`) — ইমেজ গ্যালারি (থাম্বনেইল ক্লিকে সোয়াপ), দাম+ছাড়, স্টক স্ট্যাটাস, EMI বক্স (৩/৬/১২ মাস), ডাইনামিক স্পেক টেবিল, ব্রেডক্রাম্ব, সম্পর্কিত প্রোডাক্ট সেকশন
5. Add to Cart / Wishlist বাটন প্লেসহোল্ডার (আসল লজিক Part 5-এ)

> নোট: EMI বক্সে দেখানো মাসিক কিস্তি একটা সাধারণ ৩/৬/১২-মাস হিসাব, আসল ব্যাংক EMI শর্ত ও পেমেন্ট গেটওয়ে Part 6-এ যোগ হবে। কোনো প্রোডাক্ট এখনো ডাটাবেজে নেই — টেস্ট করতে হলে অ্যাডমিন API দিয়ে (বা bulk-import CSV টেমপ্লেট দিয়ে) কিছু প্রোডাক্ট ঢোকাতে হবে।

## Part 5 — এই পার্টে যা যোগ হলো
1. **সার্চ** — `/products/search/suggest` (autocomplete, debounced), হেডারে dropdown suggestion সহ সার্চ বার, `/search?q=` পেজ (একই ফিল্টার/সর্ট/পেজিনেশন লিস্টিং লেআউট)। MongoDB টেক্সট ইনডেক্স-ভিত্তিক — পূর্ণ typo-tolerant সার্চের জন্য ভবিষ্যতে Atlas Search/Meilisearch যোগ করা যাবে
2. **কার্ট** — Guest cart (browser-generated `X-Guest-Id`, localStorage) + logged-in user cart, add/update qty/remove, **লগইন করলে automatic merge** (`POST /cart/merge`), `/cart` পেজ
3. **Wishlist** — লগইন-প্রয়োজন, প্রোডাক্ট ডিটেইলস পেজ থেকে টগল, `/wishlist` পেজ
4. **Compare** — client-side (localStorage), সর্বোচ্চ ৪টি প্রোডাক্ট, প্রোডাক্ট কার্ডে চেকবক্স, `/compare` পেজে পাশাপাশি স্পেক টেবিল
5. Testing-এর সুবিধার জন্য হালকা `/login` ও `/account` পেজ যোগ করা হলো (পূর্ণ সাইন-আপ/OTP ফ্লো ও অ্যাকাউন্ট ড্যাশবোর্ড Part 7-এ)

## Part 6 — এই পার্টে যা যোগ হলো
1. **অর্ডার সিস্টেম** — `POST /api/orders` কার্ট থেকে অর্ডার বানায় (গেস্ট ও লগইন দুইভাবেই), স্টক আগে রিজার্ভ করে (অপর্যাপ্ত হলে ৪০৯), ডেলিভারি চার্জ (ঢাকা ৳৬০, বাইরে ৳১২০ — `orders.js`-এ বদলানো যায়), অর্ডার হিস্ট্রি `GET /orders/my`, অর্ডার ডিটেইল (মালিক/গেস্ট/অ্যাডমিন), অ্যাডমিন স্ট্যাটাস ফ্লো `PATCH /orders/:id/status` (Pending → Confirmed → Shipped → Delivered/Returned, বাতিল হলে স্টক ফেরত)
2. **পেমেন্ট** — COD (সরাসরি অর্ডার), **bKash Tokenized Checkout** (grant token → create → execute, sandbox/live), Nagad ও Card-এর জন্য গেটওয়ে স্লট রেডি কিন্তু লাইভ ইন্টিগ্রেশন এখনো নেই (মার্চেন্ট ক্রেডেনশিয়াল লাগবে)। ক্রেডেনশিয়াল না থাকলে ডেভেলপমেন্টে **মক চেকআউট** চলে যাতে পুরো ফ্লো টেস্ট করা যায় (production-এ বন্ধ)
3. `GET /api/payments/callback/:method` — পেমেন্ট শেষে গেটওয়ে এখানে পাঠায়; সফল হলে অর্ডার paid+confirmed ও কার্ট খালি, ব্যর্থ হলে অর্ডার বাতিল ও স্টক ফেরত
4. **অ্যাড্রেস বুক** — `/api/account/addresses` (CRUD), চেকআউটে সেভ করা ঠিকানা বেছে নেওয়া/নতুন ঠিকানা সেভ করা
5. **ফ্রন্টএন্ড** — `/checkout` (গেস্ট/লগইন, ঠিকানা, পেমেন্ট মেথড, অর্ডার সারাংশ), `/order-confirmation/[id]`, `/checkout/failed`; কার্ট পেজের "চেকআউট" বাটন এখন কাজ করে

> নোট: bKash sandbox ক্রেডেনশিয়াল `apps/api/.env`-এ বসান (`BKASH_*`) এবং `API_PUBLIC_URL` এমন একটা URL দিন যেটা bKash পৌঁছাতে পারে। অনলাইন পেমেন্ট করা অর্ডার বাতিল করলে রিফান্ড এখনো ম্যানুয়াল।

## Part 7 — এই পার্টে যা যোগ হলো

### অ্যাডমিন প্যানেল (`/admin`, শুধু admin/staff)
1. **প্রোডাক্ট আপলোড — একটাই মোডালে সব কিছু:** ক্যাটাগরি → সাবক্যাটাগরি → ব্র্যান্ড (বাছাই করা সাবক্যাটাগরির ব্র্যান্ড আগে দেখায়), নাম, SKU (ফাঁকা রাখলে অটো), দাম, ডিসকাউন্ট দাম, স্টক, একাধিক ছবি (প্রিভিউ, ক্রম বদল, মোছা), বিবরণ, ডাইনামিক স্পেক টেবিল, ভ্যারিয়েন্ট, ফিচার্ড, পাবলিশড/ড্রাফট। একই মোডালে এডিটও হয়।
2. **স্থায়ী সংরক্ষণ:** সেভ করলে প্রোডাক্ট MongoDB-তে থেকে যায়; "মুছুন" আসলে soft delete (ডাটা মোছে না) — প্রোডাক্ট পেজে "মুছে ফেলা প্রোডাক্ট" টিক দিয়ে **ফেরত আনা** যায়। ছবি Cloudinary-তে, আর Cloudinary কী না দিলে `apps/api/uploads` ফোল্ডারে ডিস্কে সেভ হয় (লোকাল ডেভেলপমেন্টের জন্য)।
3. প্রোডাক্ট তালিকা (সার্চ, স্ট্যাটাস ফিল্টার, পাবলিশ/আনপাবলিশ, এডিট, মুছুন/ফেরত আনুন, বাল্ক ইমপোর্ট), **অর্ডার ম্যানেজমেন্ট** (স্ট্যাটাস ফ্লো, রিটার্ন অনুমোদন/প্রত্যাখ্যান), **ইনভেন্টরি** (লো-স্টক লিস্ট + ইনলাইন স্টক আপডেট), **কুপন ইঞ্জিন** (শতাংশ/ফ্ল্যাট, মেয়াদ, ন্যূনতম অর্ডার, সর্বোচ্চ ছাড়), **ইউজার ও রোল**, ড্যাশবোর্ড সামারি কার্ড

### কাস্টমার অ্যাকাউন্ট
`/signup`, `/login` (পাসওয়ার্ড + **OTP**), `/account` (লয়্যালটি পয়েন্টস — ৳১০০ = ১ পয়েন্ট, ডেলিভারড হলে জমা), `/account/orders` (ট্র্যাকিং টাইমলাইন + রিটার্ন রিকোয়েস্ট), `/account/addresses` (ঠিকানা বই)। চেকআউটে কুপন কোড প্রয়োগ।

### প্রথম অ্যাডমিন বানানো
১) `/signup` থেকে অ্যাকাউন্ট খুলুন  ২) টার্মিনালে: `npm run make-admin -- আপনার@ইমেইল`  ৩) লগআউট করে আবার লগইন করুন → `/admin` খুলবে।

> নোট: OTP কোড এখন API/web সার্ভারের কনসোলে প্রিন্ট হয় (আসল ইমেইল/SMS Part 9-এ)। পয়েন্ট আপাতত শুধু জমা হয়, খরচ (redeem) করার সুবিধা নেই। প্রোডাক্ট ও ক্যাটাগরি অ্যাডমিন পেজের নতুন ফর্মগুলো সাধারণ Tailwind দিয়ে বানানো (Gravity UI শুধু ক্যাটাগরি পেজে)।

## Part 8 — এক্সট্রা টুলস

1. **PC Builder** (`/pc-builder`) — কম্পোনেন্ট স্লট (CPU, মাদারবোর্ড, RAM, GPU, স্টোরেজ, PSU, ক্যাসিং, কুলার) থেকে একটা করে প্রোডাক্ট বাছুন। সার্ভার Socket, RAM টাইপ, ফর্ম ফ্যাক্টর, PSU ওয়াটেজ স্পেক টেক্সট থেকে মিলিয়ে কম্প্যাটিবিলিটি চেক করে এবং মোট দাম দেখায়; মিললে এক ক্লিকে সব কার্টে যোগ করা যায়। যেহেতু কোন সাবক্যাটাগরি কোন স্লটের (যেমন "Processor" স্লট আসলে কোন সাবক্যাটাগরি) — সেটা এক্সেল থেকে আসা আসল সাবক্যাটাগরি নামের সাথে নিশ্চিতভাবে মেলানো সম্ভব ছিল না, তাই **অ্যাডমিন প্যানেল → Extra Tools**-এ প্রতিটা স্লট কোন সাবক্যাটাগরি থেকে প্রোডাক্ট টানবে সেটা বেছে দিতে হবে (একবারই, সাইট বসানোর সময়)।
2. **Laptop Finder** (`/laptop-finder`) — বাজেট রেঞ্জ ও ব্যবহারের ধরন (গেমিং/অফিস/স্টুডেন্ট/এডিটিং/বিজনেস) বেছে দিলে সেই বাজেটের Laptop ক্যাটাগরির প্রোডাক্ট থেকে স্পেক-ভিত্তিক স্কোরিং করে সেরা মিল দেখায়। Laptop Finder কোন Main Category ব্যবহার করবে সেটাও অ্যাডমিন প্যানেল থেকে বাছা যায় (নাহলে নামে "Laptop" খুঁজে অটো-ডিটেক্ট করে)।
3. **AC Ton/Load ক্যালকুলেটর** (`/ac-calculator`) — সম্পূর্ণ ফ্রন্টএন্ড, কোনো ব্যাকএন্ড লাগে না। রুমের মাপ, রোদ, ফ্লোর, মানুষ ও যন্ত্রপাতির সংখ্যা দিয়ে আনুমানিক প্রয়োজনীয় টন হিসাব করে।
4. **রিভিউ ও রেটিং** — লগইন করা ইউজার প্রোডাক্ট পেজ থেকে স্টার রেটিং + কমেন্ট দিতে পারবে (একজন ইউজার প্রতি প্রোডাক্টে একটা রিভিউ, পরে আপডেট করা যায়)। ডেলিভারড অর্ডারে প্রোডাক্টটি থাকলে **"ভেরিফাইড ক্রয়"** ব্যাজ দেখায়। প্রোডাক্টের গড় রেটিং স্বয়ংক্রিয়ভাবে আপডেট হয়।

> এই তিনটা টুলের লিংক ফুটারের "টুলস" কলামে যোগ করা হয়েছে।

## Part 9 — CMS, নোটিফিকেশন, স্টোর লোকেটর

1. **হোমপেজ CMS** — ব্যানার স্লাইডার (একাধিক ব্যানার, লিংকসহ, অটো-স্লাইড), Happy Hour ব্যানার (মেয়াদ শেষ হলে নিজে থেকে হাইড হয়), ফিচার্ড প্রোডাক্ট সেকশন — সব `/admin/cms` থেকে ম্যানেজ করা যায়।
2. **ব্লগ/নিউজ** — `/blog` লিস্টিং + `/blog/[slug]` ডিটেইলস, SEO কন্টেন্টের জন্য, `/admin/blog` থেকে লেখা/এডিট/পাবলিশ।
3. **স্টোর লোকেটর** — `/store-locator`, ব্রাঞ্চ তালিকা + Google Maps embed (কোনো Maps API কী লাগে না)। `/admin/branches` থেকে ব্রাঞ্চ যোগ/এডিট করা যায়।
4. **কমপ্লেইন/ফিডব্যাক ফর্ম** — `/contact` (সাধারণ যোগাযোগ) ও `/complaint` (অভিযোগ, অর্ডার আইডিসহ) আলাদা পেজ, দুটোই একই ইনবক্সে জমা হয় — `/admin/messages` থেকে দেখা ও স্ট্যাটাস (নতুন/পঠিত/সমাধান) আপডেট করা যায়।
5. **SMS/Email নোটিফিকেশন** — অর্ডার Confirmed/Shipped/Delivered/Returned/Cancelled হলে স্বয়ংক্রিয়ভাবে SMS+Email পাঠানোর চেষ্টা হয়। SMTP/SMS ক্রেডেনশিয়াল না দিলে ডেভেলপমেন্টে এগুলো সার্ভার কনসোলে লগ হয় (মক), তাই ক্রেডেনশিয়াল ছাড়াই পুরো ফ্লো টেস্ট করা যায়। SMS গেটওয়ে (SSL Wireless/Alpha SMS ইত্যাদি) নিজের পছন্দ অনুযায়ী `apps/api/src/lib/notify.js`-এ বসাতে হবে — প্রতিটা গেটওয়ের payload আলাদা তাই এখনো জেনেরিক স্টাব হিসেবে রাখা হয়েছে।
6. **Live Chat** — সাইটের নিচে-ডানে একটা চ্যাট বাটন (গেস্ট ও লগইন দুজনের জন্যই), অ্যাডমিন `/admin/chat` থেকে রিপ্লাই দিতে পারবে। এটা রিয়েল-টাইম ওয়েবসকেট না — প্রতি ৪-৫ সেকেন্ডে পোল করে, কোনো এক্সট্রা ইনফ্রাস্ট্রাকচার ছাড়াই কাজ করে।

### একটা অনুরোধ অনুযায়ী বাদ দেওয়া হয়েছে
আগে লগইন পেজে যোগ করা **OTP লগইন সেকশন সরিয়ে ফেলা হয়েছে** — এখন শুধু পাসওয়ার্ড ও Google/Facebook দিয়ে লগইন। Better Auth-এর emailOTP প্লাগিনও কনফিগ থেকে বাদ দেওয়া হয়েছে।

> নোট: Header/Footer রুট লেআউটে বসানো, তাই /admin পেজেও সেগুলো (অ্যাডমিন সাইডবারের উপরে) দেখা যাবে — এটা একটা কসমেটিক ওভারল্যাপ, ফাংশনালিটি ভাঙে না। চাইলে Part 10 পলিশ পাসে ঠিক করে দেব।

## Part 10 — অ্যানালিটিক্স, SEO, পারফরম্যান্স ও পলিশ (শেষ পার্ট)

1. **সেলস অ্যানালিটিক্স** (`/admin/analytics`) — দৈনিক বিক্রির বার চার্ট (৭/১৪/৩০/৯০ দিন), অর্ডার স্ট্যাটাস ব্রেকডাউন, টপ ১০ প্রোডাক্ট (বিক্রি অনুযায়ী), পেমেন্ট মেথড সামারি — কোনো এক্সট্রা চার্ট লাইব্রেরি ছাড়াই (প্লেইন CSS bar), শুধু paid অর্ডারের উপর ভিত্তি করে হিসাব করা।
2. **SEO** — প্রতিটা প্রোডাক্ট/ক্যাটাগরি/সাবক্যাটাগরি/ব্র্যান্ড/ব্লগ পেজে ডাইনামিক টাইটেল-ডেসক্রিপশন-canonical-OG ট্যাগ, প্রোডাক্ট পেজে JSON-LD (schema.org Product) স্ট্রাকচার্ড ডেটা, ডাইনামিক `sitemap.xml` (সব ক্যাটাগরি/সাব/ব্র্যান্ড/প্রোডাক্ট, ঘণ্টায় একবার রিফ্রেশ) ও `robots.txt`।
3. **পারফরম্যান্স** — ক্যাটাগরি ট্রি (৫ মিনিট), প্রোডাক্ট লিস্টিং (১ মিনিট) ও ডিটেইলস ডেটার fetch-cache revalidate আগে থেকেই সেট করা ছিল; এবার লিস্টিং ও প্রোডাক্ট পেজে `loading.js` স্কেলিটন যোগ হলো যাতে ডেটা লোড হওয়ার সময় ফাঁকা স্ক্রিন না দেখায়।
4. **ডিজাইন/স্ট্রাকচার পলিশ** — **বড় ফিক্স:** আগে Header/Footer/চ্যাট রুট লেআউটে থাকায় `/admin` পেজেও সেগুলো অ্যাডমিন সাইডবারের সাথে ওভারল্যাপ করে দেখা যেত (Part 9-এ উল্লেখ করেছিলাম) — এখন সেগুলো `app/(shop)/layout.js`-এ সরিয়ে নেওয়া হয়েছে, root layout খালি থাকে, তাই `/admin` পুরোপুরি নিজের সাইডবার লেআউটে চলে, storefront chrome আর দেখায় না। এছাড়া storefront-এর জন্য 404 ও error পেজ যোগ হলো।
5. **QA / পরিচিত সীমাবদ্ধতা** — পুরো প্রজেক্টের কোড এই কন্টেইনারে `npm install` করে রান-টাইমে টেস্ট করা যায়নি (ইন্টারনেট নেই); প্রতিটা পার্টে সিনট্যাক্স-লেভেল চেক পাস করেছে। যা এখনো নিজে করে দেখতে হবে/যোগ করতে হবে:
   - `npm install` করে dev সার্ভার (`npm run dev:api`, `npm run dev:web`) চালিয়ে পুরো ফ্লো (সাইনআপ → প্রোডাক্ট আপলোড → কার্ট → চেকআউট → অ্যাডমিন অর্ডার আপডেট) হাতে-কলমে টেস্ট করা
   - Nagad ও Card পেমেন্ট গেটওয়ে (এখনো মক), SMS গেটওয়ে (এখনো মক)
   - প্রথম অ্যাডমিন তৈরি: `npm run make-admin -- ইমেইল`
   - PC Builder ও Laptop Finder-এর ক্যাটাগরি ম্যাপিং (`/admin/tools`) একবার সেট করা
   - ৫,০০০-এর বেশি প্রোডাক্ট হলে sitemap-কে sitemap-index প্যাটার্নে ভাঙা লাগবে (এখন এক ফাইলে সর্বোচ্চ ৫০০০টা প্রোডাক্ট ধরে)
   - প্রোডাকশনে যাওয়ার আগে সব `.env.example`-এর মান বসিয়ে real credentials দেওয়া (MongoDB, Better Auth secret, Cloudinary, bKash, SMTP ইত্যাদি)
